# PRD 작성 프롬프트

## 역할 설정
너는 세계 최고의 프롬프트 엔지니어이자, 20년 경력의 시니어 프로덕트 매니저다. 
다음 정보를 바탕으로 완벽하고 상세한 PRD(Product Requirements Document)를 작성해줘.

## 입력 정보
- **타겟 사용자**: {타겟_사용자}
- **주요 기능**: {주요_기능_리스트}
- **데이터 소스**: {데이터_소스}
- **플랫폼**: {플랫폼}
- **기술 스택**: {기술_스택}

## PRD 작성 가이드라인

### 1. 문서 구조
다음 섹션들을 반드시 포함해야 해:

#### 1.1 Executive Summary (요약)
- 프로덕트의 핵심 가치 제안
- 목표와 성공 지표
- 주요 특징 요약

#### 1.2 Problem Statement (문제 정의)
- 해결하려는 문제
- 타겟 사용자의 페인 포인트
- 현재 시장의 한계점

#### 1.3 Solution Overview (솔루션 개요)
- 프로덕트의 핵심 솔루션
- 주요 기능의 하이레벨 설명
- 차별화 포인트

#### 1.4 Target Users (타겟 사용자)
- 사용자 페르소나 (Persona)
- 사용자 여정 (User Journey)
- 사용 사례 (Use Cases)

#### 1.5 Features & Requirements (기능 및 요구사항)
각 기능에 대해 다음을 포함:
- **기능명**: 명확한 이름
- **설명**: 기능의 목적과 가치
- **우선순위**: Must Have / Should Have / Nice to Have
- **상세 요구사항**: 
  - 기능적 요구사항 (Functional Requirements)
  - 비기능적 요구사항 (Non-functional Requirements)
- **사용자 스토리**: "As a [사용자], I want to [행동] so that [목적]"
- **수용 기준**: 명확한 완료 조건

#### 1.6 User Stories & Acceptance Criteria (사용자 스토리 및 수용 기준)
- 각 기능별 상세 사용자 스토리
- 명확한 수용 기준 (Acceptance Criteria)
- 에지 케이스 고려

#### 1.7 Technical Requirements (기술 요구사항)
- 기술 스택 상세
- 아키텍처 개요
- 데이터 모델
- API 설계
- 성능 요구사항
- 보안 요구사항
- 확장성 고려사항

#### 1.8 Data Requirements (데이터 요구사항)
- 데이터 소스 상세
- 데이터 구조
- 데이터 업데이트 주기
- 데이터 품질 요구사항

#### 1.9 Design Requirements (디자인 요구사항)
- UI/UX 원칙
- 디자인 시스템 요구사항
- 반응형 디자인 요구사항
- 접근성 요구사항

#### 1.10 Success Metrics (성공 지표)
- 정량적 지표 (KPI)
- 정성적 지표
- 측정 방법

#### 1.11 Timeline & Milestones (타임라인 및 마일스톤)
- 개발 단계
- MVP 범위
- 주요 마일스톤
- 릴리스 계획

#### 1.12 Risks & Mitigation (리스크 및 완화 방안)
- 기술적 리스크
- 비즈니스 리스크
- 완화 전략

#### 1.13 Future Considerations (향후 고려사항)
- Phase 2 기능
- 장기 로드맵
- 확장 가능성

### 2. 작성 원칙
- **명확성**: 모호함 없이 구체적으로 작성
- **측정 가능성**: 모든 요구사항은 검증 가능해야 함
- **실행 가능성**: 실제 구현 가능한 범위 내에서 작성
- **사용자 중심**: 항상 사용자 관점에서 작성
- **기술적 정확성**: 기술 스택에 맞는 구체적인 요구사항

### 3. 상세도 레벨
- 각 기능은 개발자가 바로 구현할 수 있을 정도로 상세하게
- 예시와 시나리오를 풍부하게 포함
- 에러 케이스와 엣지 케이스도 고려
- API 엔드포인트, 데이터 구조 등 기술적 세부사항 포함

### 4. 특별 고려사항
- Flutter 웹 개발의 특성 반영
- 개발자 타겟이므로 기술적 정확성 중시
- API 기반 데이터 수집 전략
- 비교 기능의 UX/UI 고려
- 필터/검색의 성능 최적화

## 출력 형식
마크다운 형식으로 작성하고, 각 섹션은 명확하게 구분되어야 함.
코드 블록, 다이어그램, 표 등을 적절히 활용하여 가독성을 높여야 함.
