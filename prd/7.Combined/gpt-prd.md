# LLM Popularity Tracker PRD (통합본 v1.0)

## 1) Executive Summary
- **제품 목적**: 다양한 LLM의 정보를 한 곳에서 제공하고, **다각도 인기도 지표**를 통해 사용자가 LLM을 탐색/비교/의사결정할 수 있게 한다.
- **핵심 가치**
  - **탐색 효율**: 목록/검색/필터로 후보를 빠르게 좁힘
  - **비교 가능성**: 동일한 데이터 모델로 스펙/지표를 나란히 비교
  - **신뢰성**: "인기도"를 단일 점수로 뭉개지 않고 **카테고리 분리 + 계산 규칙 공개**
- **플랫폼**: Flutter Web (Chrome/Edge/Firefox/Safari 최신 2개 버전), 반응형(모바일/태블릿/데스크톱)

## 2) Problem Statement
- LLM 정보가 GitHub/HF/논문/커뮤니티 등으로 흩어져 있고 기준도 다르다.
- "인기"의 의미가 사용자(개발자/연구자/의사결정자)마다 달라 단일 지표만으로는 의사결정이 어렵다.
- 최신 트렌드를 추적하기 위해 반복 수집/정리가 필요하다.

## 3) Goals / Non-Goals
- **Goals**
  - LLM 탐색 시간을 단축하고(목표 50%), 지표 기반으로 비교/선택할 수 있게 한다.
  - 인기도를 **4개 카테고리**로 제공하고, 사용자가 원하면 가중치로 **통합 점수**를 만든다.
- **Non-Goals (v1)**
  - 사용자 계정/로그인(즐겨찾기 서버 동기화)
  - 실시간(초 단위) 업데이트
  - "LLM 직접 실행/테스트 샌드박스"

## 4) Target Users & User Journeys
- **페르소나**
  - **개발자**: OSS/상용 비교, 스펙/라이선스/레퍼런스 중시
  - **연구자**: 논문/인용/영향력 중시
  - **의사결정자**: 트렌드/리스크/요약 정보 선호
- **핵심 여정**
  1) 홈/목록 → 검색/필터 → 상세 → 비교(선택)
  2) 설정에서 "가중치 프리셋" 선택 → Top 10/정렬 기준이 즉시 반영

## 5) Information Architecture (Screens)
- **S1. 홈/목록**: 검색바, 빠른 필터(프리셋), 정렬, 카드 그리드, 페이지네이션
- **S2. 상세**: 기본 정보 + 인기도(카테고리별) + 트렌드 + 링크 + 관련 모델
- **S3. 비교**: 최대 5개, 테이블/차트 병행, 모바일은 세로 카드 비교
- **S4. 설정**: 가중치 슬라이더, 프리셋(개발자 중심/연구자 중심/실용 중심), 다크모드

## 6) Popularity Model (핵심 정의)
### 6.1 카테고리(0~100)
- **A. 개발자 커뮤니티 인기도**
  - GitHub Stars(40), Forks(20), Issues/PR 활동(20), StackOverflow(20)
- **B. 학술적 영향력**
  - 인용수(60), 관련 논문수(20), 최근 1년 증가율(20)
- **C. 실용적 채택도**
  - Hugging Face 다운로드(50), PyPI 다운로드(30), Docker Pulls(20)
- **D. 커뮤니티 활성도**
  - Reddit 게시물(30), 커뮤니티 규모(30), 최근 30일 증가율(40)

### 6.2 통합 점수(선택)
- 기본값: \(W1=0.4, W2=0.2, W3=0.3, W4=0.1\)
- 사용자가 슬라이더로 \(W1~W4\) 조정(합 1.0)

### 6.3 정규화/결손 처리(중요)
- **정규화**: 각 원천 지표는 기간(예: 최근 6개월) 내 관측치로 0~100 선형 스케일링
- **결손(N/A)**:
  - 특정 LLM에 지표가 없으면 해당 지표 가중치를 **동일 카테고리 내 다른 지표로 재분배**
  - 카테고리 자체가 결손이면 통합 점수 계산에서 해당 카테고리를 제외하고 \(W\)를 재정규화
- **표시 규칙**: UI에는 `N/A`와 함께 "데이터 없음(사유)" 툴팁, "마지막 업데이트 시각" 노출

## 7) Data Strategy (하이브리드 v1)
- **v1 권장**: 정적 JSON(앱 asset) + GitHub Actions 스케줄로 데이터 갱신
- **업데이트 주기(기본)**: 일 1회(개발자/채택도), 주 1회(학술/커뮤니티)
- **v2 옵션**: Backend API로 중앙화(레이트리밋/키 관리/집계)

## 9) Features (FR/NFR/AC 요약)
### F1. 목록/탐색(검색/필터/정렬)
- **FR**
  - 이름/개발사/태그 검색(디바운스)
  - 필터: 라이선스, 오픈소스 여부, 출시일 범위, 파라미터 범위, 지원 기능
  - 정렬: 카테고리별 점수, 통합 점수(가중치 반영), 출시일
- **NFR**: 검색 반응 300ms 이내(로컬 데이터 기준), 스크롤 60fps 유지
- **AC**
  - 필터 상태가 URL(또는 로컬 상태)로 유지되고 "초기화" 동작이 일관됨
  - 데이터 없음/결손은 `N/A`로 표시되며 정렬에서 예측 가능하게 처리됨(예: N/A는 하단)

### F2. 상세 페이지(지표/트렌드/설명)
- **FR**
  - 4카테고리 점수 + 근거 지표(툴팁/모달) + 마지막 업데이트
  - 최근 6개월 트렌드 라인 차트
- **NFR**: 차트 렌더 1초 이내(중간급 모바일 포함)
- **AC**
  - 지표 클릭 시 출처/설명/원천 값/정규화 값이 노출됨
  - 결손 지표는 이유와 함께 노출됨("GitHub repo 없음" 등)

### F3. 비교(최대 5개)
- **FR**
  - 비교 바(고정)에서 추가/제거, 2개 이상이면 "비교하기" 활성화
  - 테이블 + 바차트(카테고리 점수)
  - 공유 링크(쿼리로 ids 보존)
- **NFR**: 5개 비교 렌더 1초 이내
- **AC**
  - 모바일은 가로 스크롤 대신 세로 비교로 접근 가능

### F4. 설정(가중치/프리셋/다크모드)
- **FR**
  - 프리셋: 개발자/연구자/실용 중심
  - 가중치 합 1.0 강제(UX: 나머지 자동 보정)
- **AC**
  - 가중치 변경 즉시 Top 10/정렬 결과가 반영됨

## 10) Non-Functional Requirements
- **접근성(WCAG 2.1 AA)**: 키보드 포커스, 명도 대비, 차트 대체 텍스트/요약 제공
- **보안**: (v2에서) API 키는 서버에서만 관리, 클라이언트에 노출 금지
- **성능 목표**: 초기 화면 의미 있는 콘텐츠 2~3초 내, 이미지 lazy load, 캐시 적용

## 11) Tech Stack (Flutter Web)
- **상태 관리**: Riverpod(권장) 또는 Provider
- **라우팅**: `go_router`
- **HTTP**: `dio`(v2에서) / v1은 asset 로드
- **차트**: `fl_chart` (또는 요구 시 Syncfusion)
- **캐시**: `shared_preferences`(가중치/프리셋), (필요시) Hive(오프라인 데이터)

## 12) Testing & Analytics
- **테스트**
  - 단위: 인기도 계산/정규화/결손 재분배 로직
  - 위젯: 목록/필터/정렬/비교/설정 인터랙션
  - 통합: 라우팅/딥링크(비교 링크)
- **측정(KPI)**
  - 검색 사용률, 비교 진입률, 설정(가중치) 사용률
  - 상세 페이지 체류/이탈, 로딩 시간(간단 로그)

## 13) Milestones (권장)
- **MVP(4~6주)**: 목록+상세(기본 지표 2개) + 검색/기본 필터 + 정적 데이터
- **v1(추가 4~6주)**: 4카테고리 지표 + 트렌드 + 비교 + 설정(가중치)
- **v2(선택)**: 백엔드 중앙화/자동 집계/레이트리밋 관리

## 14) Risks & Mitigation
- **데이터 가용성/레이트리밋**: 하이브리드 업데이트 + 캐시 + 결손 처리 UI
- **Flutter Web 번들/성능**: 이미지 최적화, 차트 최소화, 리스트 가상화 고려
- **지표 신뢰성**: 출처/업데이트 시각/정규화 방식을 UI에 투명하게 노출
