# LLM 인기도 웹사이트 PRD (Tree of Thoughts 분석)

## 프로젝트 개요
AI에서 사용하는 LLM(Large Language Model)의 종류와 인기도를 시각화하고 비교할 수 있는 웹사이트를 개발합니다.

---

## Tree of Thoughts: 세 가지 전략 분석

### 🌳 전략 1: 정적 데이터 기반 웹사이트

#### 개념
- 수동으로 데이터를 수집하여 정적 파일로 저장
- 간단한 프론트엔드로 데이터를 시각화
- Flutter Web 또는 순수 HTML/CSS/JS 사용

#### 장점
- ✅ 개발 속도가 빠름 (1-2주)
- ✅ 서버 비용 없음 (호스팅만 필요, 월 $0-5)
- ✅ 유지보수가 간단함
- ✅ 초기 개발 비용이 낮음
- ✅ 오프라인에서도 작동 가능

#### 단점
- ❌ 데이터가 자동으로 업데이트되지 않음
- ❌ 수동 업데이트 필요 (시간 소모)
- ❌ 실시간성이 부족
- ❌ 데이터 소스가 제한적 (공개된 정보만 활용)

#### 예상 비용
- **개발 비용**: 40-80시간 (개발자 1명 기준)
- **인프라 비용**: 월 $0-5 (GitHub Pages, Netlify 등 무료 호스팅)
- **유지보수 비용**: 월 5-10시간 (데이터 수집 및 업데이트)
- **총 초기 비용**: $2,000-4,000 (시간당 $50 기준)
- **월 운영 비용**: $250-500 (유지보수)

---

### 🌳 전략 2: 동적 데이터 수집 웹사이트

#### 개념
- 다양한 API를 통해 실시간으로 데이터 수집
  - GitHub Stars/Forks
  - Hugging Face 다운로드 수
  - 논문 인용 수 (Google Scholar, arXiv)
  - Reddit/Discord 활동량
  - 트위터/X 언급 수
- 백엔드 서버에서 주기적으로 데이터 수집 및 저장
- REST API 또는 GraphQL로 프론트엔드에 제공

#### 장점
- ✅ 실시간 데이터 업데이트
- ✅ 다양한 데이터 소스 통합 가능
- ✅ 사용자에게 최신 정보 제공
- ✅ 확장성 높음 (새로운 데이터 소스 추가 용이)
- ✅ 자동화된 데이터 수집

#### 단점
- ❌ 개발 복잡도 높음 (3-4개월)
- ❌ 서버 인프라 필요 (월 $50-200)
- ❌ API 비용 발생 가능 (일부 API는 유료)
- ❌ 유지보수 복잡 (API 변경 대응 필요)
- ❌ 초기 개발 비용이 높음

#### 예상 비용
- **개발 비용**: 200-400시간 (백엔드 + 프론트엔드)
- **인프라 비용**: 월 $50-200 (서버, 데이터베이스, API 호출)
- **유지보수 비용**: 월 20-40시간 (API 모니터링, 버그 수정)
- **총 초기 비용**: $10,000-20,000
- **월 운영 비용**: $1,000-2,000 (인프라 + 유지보수)

---

### 🌳 전략 3: 하이브리드 방식 (정적 생성 + 주기적 업데이트)

#### 개념
- 기본 데이터는 정적으로 유지
- GitHub Actions 또는 간단한 스크립트로 주기적(일/주 단위) 데이터 수집
- 수집한 데이터를 정적 JSON 파일로 변환하여 저장
- 프론트엔드는 정적 파일을 읽어서 표시
- JAMstack 아키텍처 활용

#### 장점
- ✅ 자동화된 데이터 업데이트 (스케줄링)
- ✅ 서버 비용 최소화 (빌드 시에만 실행)
- ✅ 정적 호스팅의 빠른 속도
- ✅ 개발 복잡도 중간 수준 (1-2개월)
- ✅ API 비용 최소화 (빌드 시에만 호출)
- ✅ 확장 가능 (새로운 데이터 소스 추가 용이)

#### 단점
- ⚠️ 실시간은 아니지만 거의 실시간 (최대 1일 지연)
- ⚠️ 빌드 시간이 길어질 수 있음 (데이터 소스 많을 경우)
- ⚠️ 초기 설정이 전략 1보다 복잡

#### 예상 비용
- **개발 비용**: 80-160시간 (스크립트 + 프론트엔드)
- **인프라 비용**: 월 $0-10 (GitHub Actions 무료 티어 또는 Vercel/Netlify)
- **유지보수 비용**: 월 5-15시간 (스크립트 모니터링, 데이터 소스 추가)
- **총 초기 비용**: $4,000-8,000
- **월 운영 비용**: $250-750 (유지보수 + 인프라)

## 🎯 가지치기: 비합리적인 전략 제거

### 제거된 전략: **전략 2 (동적 데이터 수집 웹사이트)**

#### 제거 이유
1. **과도한 비용**: 초기 개발 비용이 $10,000-20,000로 매우 높음
2. **복잡한 인프라**: 서버, 데이터베이스, 모니터링 시스템 등이 필요
3. **과도한 기능**: LLM 인기도 웹사이트라는 목적에 비해 너무 복잡함
4. **유지보수 부담**: API 변경, 서버 관리 등 지속적인 관리 필요
5. **ROI 불확실**: 초기 단계에서 이 정도 투자는 과도함

---

## ✅ 최종 선택: 전략 3 (하이브리드 방식)

### 선택 이유

1. **비용 효율성**
   - 초기 비용: $4,000-8,000 (전략 2의 절반)
   - 월 운영 비용: $250-750 (전략 2의 1/4 수준)
   - 무료 호스팅 옵션 활용 가능

2. **자동화와 단순함의 균형**
   - 자동으로 데이터 업데이트 (전략 1의 단점 해결)
   - 복잡한 서버 인프라 불필요 (전략 2의 단점 회피)
   - GitHub Actions로 무료 자동화 가능

3. **확장성**
   - 필요시 새로운 데이터 소스 추가 용이
   - 정적 사이트의 빠른 로딩 속도
   - CDN을 통한 글로벌 배포 용이

4. **개발 속도**
   - 1-2개월 내 완성 가능 (전략 2보다 빠름)
   - Flutter Web 활용 가능 (기존 프로젝트와 일관성)

5. **유지보수 용이성**
   - 정적 파일 기반으로 디버깅 쉬움
   - 서버 다운 걱정 없음
   - 스크립트만 모니터링하면 됨

## 📋 최종 PRD 상세

### 1. 프로젝트 목표
LLM의 종류와 인기도를 시각화하여 사용자가 쉽게 비교하고 탐색할 수 있는 웹사이트를 제공합니다.

### 2. 핵심 기능

#### 2.1 LLM 목록 및 상세 정보
- 주요 LLM 목록 표시 (GPT-4, Claude, Llama, Mistral 등)
- 각 LLM의 기본 정보:
  - 모델 이름 및 버전
  - 개발사/조직
  - 출시일
  - 모델 크기 (파라미터 수)
  - 컨텍스트 길이
  - 라이선스

#### 2.2 인기도 지표 시각화
- **GitHub Stars/Forks**: 오픈소스 모델의 경우
- **Hugging Face 다운로드 수**: Hugging Face에 등록된 모델
- **논문 인용 수**: 학술 논문이 있는 경우
- **트렌드 그래프**: 시간에 따른 인기도 변화
- **비교 차트**: 여러 LLM을 동시에 비교

#### 2.3 검색 및 필터링
- 모델 이름으로 검색
- 필터링 옵션:
  - 파라미터 수 범위
  - 라이선스 유형
  - 출시일
  - 개발사

#### 2.4 반응형 디자인
- 모바일, 태블릿, 데스크톱 지원
- Flutter Web으로 구현

### 3. 기술 스택

#### 프론트엔드
- **Flutter Web**: 기존 프로젝트와 일관성 유지
- **상태 관리**: Provider 또는 Riverpod
- **차트 라이브러리**: fl_chart 또는 charts_flutter
- **HTTP 클라이언트**: http 패키지

#### 데이터 수집
- **Python 스크립트**: 데이터 수집 및 변환
- **GitHub Actions**: 주기적 실행 (매일 또는 매주)
- **데이터 소스 API**:
  - GitHub API (Stars, Forks)
  - Hugging Face API (다운로드 수)
  - Google Scholar API 또는 웹 스크래핑 (인용 수)

#### 데이터 저장
- **JSON 파일**: 정적 데이터 저장
- **GitHub Repository**: 버전 관리 및 호스팅

#### 호스팅
- **GitHub Pages** 또는 **Netlify**: 무료 정적 호스팅
- **Vercel**: 대안 옵션

### 5. 개발 단계

#### Phase 1: 기본 구조 (2주)
- Flutter Web 프로젝트 설정
- 기본 UI 레이아웃 구성
- JSON 데이터 파싱 및 표시

#### Phase 2: 데이터 수집 스크립트 (2주)
- Python 스크립트 개발
- GitHub API 연동
- Hugging Face API 연동
- JSON 파일 생성

#### Phase 3: 시각화 (2주)
- 차트 라이브러리 통합
- 인기도 지표 시각화
- 비교 기능 구현

#### Phase 4: 검색 및 필터링 (1주)
- 검색 기능 구현
- 필터링 기능 구현

#### Phase 5: 자동화 및 배포 (1주)
- GitHub Actions 설정
- 정적 호스팅 설정
- 최적화 및 테스트

### 6. 성공 지표

- **사용자 경험**: 페이지 로딩 시간 < 2초
- **데이터 정확성**: 주 1회 이상 업데이트
- **접근성**: 모바일 친화적 디자인
- **확장성**: 새로운 LLM 추가 용이

### 7. 향후 확장 계획

- 사용자 리뷰 및 평점 기능
- 벤치마크 성능 비교
- 커뮤니티 포럼 연동
- API 제공 (다른 개발자들이 활용)
